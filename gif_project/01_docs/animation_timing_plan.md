# Animation Timing Plan

## 목적

각 자산의 이미지 프레임 수는 그대로 유지하면서 레이어마다 독립적인
재생 속도와 반복 정책을 적용한다. 아래 수치는 초안이며 최종 조립
프리뷰에서 장면 리듬을 확인한 뒤 조정할 수 있다.

## 권장 설정

### hero_walk

- 이미지 프레임: 4개
- 프레임당 duration: `180ms`
- 반복 정책: 반복 루프
- 속도를 늦추기 위해 hero 스프라이트를 다시 생성하거나 중복 저장하지 않는다.

### hero_walk_dev (`test` 활성)

- 이미지 프레임: `hero_walk_01.png`~`hero_walk_06.png`, 정확히 6개
- 적용 duration: 프레임당 `120ms`
- 조정 허용 범위: 프레임당 `110~130ms`
- 적용 1루프: `720ms`
- 반복 정책: 반복 루프
- 기존 4프레임 `180ms × 4 = 720ms`와 같은 전체 보행 주기를 유지한다.
- `magic_effect` 정렬을 위해 보석 중심 좌표 안정성을 최우선으로 한다.
- 프로젝트 정렬 기준 보석 중심은 프레임 내부 `(259, 78)`,
  장면 기준 `(884, 422)`로 고정한다.

### dragon_walk

- 이미지 프레임: 4개
- 프레임당 duration: `180ms`
- 반복 정책: 반복 루프
- 속도를 늦추기 위해 dragon 스프라이트를 다시 생성하거나 중복 저장하지 않는다.

### paper_effect

- 이미지 프레임: 4개
- 프레임당 duration: 약 `140ms`
- 반복 정책: 반복 루프

### magic_effect

- 이미지 프레임: 4개
- 프레임당 duration: 약 `140ms`
- 반복 정책: 반복 루프

### speech_bubble_text

- 이미지 프레임: 정확히 10개
- 단계당 duration: 약 `120ms`
- 마지막 F10 duration: 약 `1200~1600ms`
- 권장 검수값: `1400ms`
- 반복 정책: 한 번 재생한 뒤 F10 완성 상태 유지

### lower_banner_text

- 예정 이미지 프레임: 6개
- 단계당 duration: 약 `180~220ms`
- 반복 정책: 한 번 재생한 뒤 마지막 프레임 유지

## 최소공배수 타임라인을 사용하지 않는 이유

4프레임, 6프레임, 10프레임 자산을 맞추기 위해 최소공배수인 60장이나
그 배수의 120장 타임라인을 이미지로 저장하지 않는다. 이 방식은 동일한
픽셀 화면을 반복 저장하고, 작은 속도 변경에도 전체 프레임을 다시
생성해야 하며, GIF 용량도 불필요하게 증가시킨다.

대신 각 레이어는 전체 재생 시간 `t`에서 독립적으로 현재 프레임을 선택한다.

```text
hero_index   = floor(t / 180ms) mod 4
dragon_index = floor(t / 180ms) mod 4
paper_index  = floor(t / 140ms) mod 4
magic_index  = floor(t / 140ms) mod 4

speech_index = min(floor((t - speech_start) / 120ms), 9)
```

speech가 F10에 도달한 뒤에는 `speech_index=9`를 유지한다. lower banner도
같은 방식으로 마지막 인덱스를 고정한다.

## 최종 GIF 합성 원칙

1. 모든 레이어의 다음 상태 변경 시각을 계산한다.
2. 하나 이상의 레이어가 바뀌는 시각에서만 새 합성 프레임을 만든다.
3. 각 합성 프레임의 GIF duration은 다음 변경 시각까지의 시간으로 기록한다.
4. 연속된 합성 결과가 픽셀 단위로 같으면 별도 이미지를 저장하지 않고
   이전 GIF 프레임의 duration에 시간을 합산한다.
5. 마지막 완성 문장 유지도 동일한 이미지를 여러 장 복제하지 않고
   하나의 긴 duration으로 표현한다.

이 방식으로 자산별 프레임 수와 속도를 독립적으로 유지하면서 중복 화면을
최소화할 수 있다.

## lower_banner_text 확정 타이밍

- 이미지 프레임: 정확히 6개
- F1~F5 권장 duration: 프레임당 `200ms`
- 단계별 조정 허용 범위: 프레임당 `180~220ms`
- F6 권장 duration: `1400ms`
- 최종 프레임 유지 허용 범위: `1200~1600ms`
- 재생 정책: F1 → F6을 한 번 재생한 뒤 F6 유지
- 무한 반복 금지
- 같은 화면을 유지하기 위한 중복 이미지 프레임 저장 금지
- 최종 유지 시간은 F6의 GIF frame duration으로 병합

최종 조립 시 상태 인덱스는 다음처럼 계산한다.

```text
lower_banner_text_index =
  min(floor((t - lower_banner_text_start) / 200ms), 5)
```

실제 조립에서는 F1~F5의 개별 duration을 `180~220ms` 범위에서 조정할 수 있으며,
F6 도달 뒤에는 인덱스 `5`를 유지한다. 4프레임·6프레임·10프레임 자산의
최소공배수에 맞춘 60장 또는 120장 타임라인을 만들지 않는다. 각 레이어의
독립된 duration을 기준으로 상태가 바뀌는 시점에만 합성 프레임을 생성한다.

## vine_cluster_A 타이밍

- 이미지 프레임: 정확히 4개
- 권장 duration: 프레임당 `320ms`
- 조정 허용 범위: 프레임당 `280~360ms`
- 전체 권장 루프: 약 `1280ms`
- 재생 정책: 느린 반복 루프
- hero/dragon 걷기 및 magic/paper effect보다 느리게 재생
- 다른 식생 자산과 완전히 같은 위상 사용 금지
- 프레임 수를 늘려 속도를 늦추지 않고 GIF frame duration으로 제어

```text
vine_cluster_A_index = floor((t + vine_phase_offset) / 320ms) mod 4
```

`vine_phase_offset`은 향후 다른 식생 자산과 동시 제작될 때 같은 프레임이 동시에
바뀌지 않도록 서로 다른 값을 사용한다.

## lantern_glow 타이밍

- 이미지 프레임: 정확히 4개
- 권장 duration: 프레임당 `300ms`
- 조정 허용 범위: 프레임당 `250~350ms`
- 전체 권장 루프: 약 `1200ms`
- 재생 정책: 부드러운 반복 루프
- hero/dragon보다 느린 조명 호흡 느낌
- 프레임 수를 늘려 속도를 늦추지 않고 GIF frame duration으로 제어

```text
lantern_glow_index = floor(t / 300ms) mod 4
```

`test`의 최신 `lantern_glow_sheet.png`는 네 랜턴이 같은 프레임 위상으로
호흡한다. 최종 조립은 기존처럼 시트 프레임 하나를 `(0,0)`에 합성하며
랜턴별 타임라인을 따로 늘리거나 중복 이미지를 생성하지 않는다.
기존의 랜턴별 위상 차이가 필수라면 합성기가 아니라 원본 발광 시트의
별도 수정·승인이 필요하다.
